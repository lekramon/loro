# Sources and manual release search

Label: ready-for-agent
State: in-progress

## Sequence

Ticket 01 configures one Torznab-compatible source and discovers capabilities. Ticket 02 implements manual movie release search and candidate/profile explanations. Ticket 05 preserves that active-source contract while allowing multiple saved source configurations. No runtime dependency on Prowlarr/Jackett is introduced; Prowlarr can remain only the user's source of configuration values.

## Ticket 01 contract

- SRC-001: GET/PUT `/api/v1/source` manages one source. Unconfigured response: configured=false, revision=0, empty name/url, hasApiKey=false, capabilities=null, checkedAt=null. PUT requires onboarding, revision (0 initially), trimmed UTF-8 name 1–100 characters and exact HTTP(S) endpoint up to 2048 characters. Reject userinfo/query/fragment, missing host and invalid port. Preserve the endpoint path without appending /api. Supply API key separately: ASCII non-whitespace/non-control, up to 1024 characters; write-only in private SQLite, never logs/responses. HTTP supports self-hosted sources; HTTPS uses certificate validation. Save makes no external request.
- SRC-002: Blank/omitted apiKey preserves the existing key. clearApiKey:true explicitly clears it and cannot accompany a nonblank replacement. Endpoint changes require a nonblank replacement or explicit clear; never silently send an old key to a different endpoint. Revision compare-and-swap increments revision and clears cached capability evidence; stale/concurrent writes return 409 source-changed. Credentials and submitted URLs are omitted from errors.
- SRC-003: GET `/api/v1/source/test` performs a fresh saved-endpoint request with t=caps and optional apikey. One active test, no redirects, 2-second attempt deadline, 4 total transient network/5xx attempts with 100/200/400ms backoff within 10 seconds. Never retry auth/malformed/429. Retry-After bounded to 1–3600 seconds establishes a process-local cooldown scoped to config revision. Query credentials and upstream response bodies never enter diagnostics.
- SRC-004: XML limits: 2 MiB, depth 32, 20,000 tokens, 256 normalized categories, bounded names/known supportedParams. Reject directives/DTD, malformed/multiple documents and non-caps success. Parse search/movie-search available/supportedParams, optional limits, category/subcategory IDs and names. Missing limits remain null. Ignore server metadata, URLs and images; never fetch links. Redact key occurrences from category names. HTTP 401/403 or Torznab error code 100/101/102 means authentication failure. Classify timeout, rate limit, malformed response and unavailable separately.
- SRC-005: Successful test returns connected=true, sourceRevision, capabilities and local checkedAt; save evidence only if the revision still matches. Config changes during the call return 409 without publishing stale success. GET exposes public configuration and last successful capabilities/time. Caps success proves connectivity, not search authentication: some providers expose caps without requiring a key. Reflect absent movie/generic capabilities honestly.
- SRC-006: Additive migration 6 creates source configuration storage; preserve settings/catalog/inventory/associations and private TMDB file. Readiness validates the new table. Older binaries reject 6; rollback restores a matching pre-upgrade stopped-service backup. External outages do not affect readiness or offline catalog. Never auto-run destructive Down migrations.
- SRC-007: Settings has a localized Source form: name, endpoint, password API key, explicit clear checkbox, save/test, key-presence and last successful capability state. Clear typed secrets after save/failure; no browser persistence/prefill. Disable testing while unsaved edits exist. Show sanitized classified errors and capability-versus-authentication distinction. Preserve shared header, themes/locales. Do not expose nonfunctional release-search controls.

[Wire contract](openapi.json). Errors: 400 malformed/unknown/duplicate JSON; 403 Host/Origin/header; 413 body limit; 415 content type; 422 invalid config; 409 setup-required/source-changed/source-test-in-progress; 503 source-unconfigured/source-authentication-failed/source-unavailable/storage-unavailable; 504 source-timeout; 429 source-rate-limited with Retry-After; 502 source-invalid-response. GET works before setup; PUT requires setup. Test accepts no query or body.

## Ticket 02 boundary

- REL-001: GET `/api/v1/releases?movieId=<catalog ID>&limit=25&offset=0&category=<optional ID>` requires completed setup, a registered movie and successfully tested source capabilities. Reject unknown/duplicate query keys, bodies, invalid IDs, limit outside 1–50, offset outside 0–10000 and category absent from discovered capabilities. Clamp the effective limit to the source maximum. No TMDB network request is needed for registered movies. Prefer `t=movie&tmdbid` when declared, then `t=movie&q` using original title (display title fallback) and declared year; otherwise `t=search&q` with title and known year. Unsupported search returns 409. Send `extended=1`, limit/offset and selected category; no automatic category inference.
- REL-002: Reuse the source transport's deadlines, retry/cooldown, no-redirect and XML limits. Allow one test/search operation at a time. Require RSS/channel; at most the effective limit of items, no more than 50. Reject malformed pagination or a supplied response offset different from requested. Response total is nullable; hasMore uses supplied total, otherwise a full raw page (a next empty page is possible). Deduplicate identical candidate IDs within the page while retaining raw-page pagination. nextOffset advances by raw item count, including duplicates, and is null at the end or the 10000 offset bound; do not skip items on short provider pages. Never fetch links, enclosures, magnets, artwork or torrent bytes.
- REL-003: Each candidate has an opaque SHA-256 ID scoped to source revision and provider GUID; without GUID use title plus enclosure/link as identity input. Omit raw GUIDs, links and all credentials from public output. IDs identify observations, not verified torrent identity or durable acquisitions. Return bounded, control-free titles with API key occurrences redacted; nullable nonnegative size/seeders (maximum JSON-safe integer 9007199254740991, also bounding totals) and normalized publication time; conflicting/invalid numeric evidence becomes null. Missing title or identity is an invalid response. No result is hidden by profile status. Keep source order.
- REL-004: Infer resolution only from explicit 480p/576p/720p/1080p/2160p title tokens or exact resolution attribute; conflicting evidence is unknown. Parse Remux, BluRay, WEB-DL, WEBRip, HDTV and DVD title tokens (Remux supersedes BluRay); conflicting formats are unknown. Container requires an explicit supported title token/extension. Audio requires explicit language attributes mapped to supported ISO codes or unambiguous language names; subtitles, audio codecs, DUAL/MULTI and original title language are not proof of audio language. No language title guessing. Unknown values are null/empty arrays, never defaults.
- REL-005: Return sourceRevision and profileRevision with four checks (resolution, format, container, audio), each match/mismatch/unknown with the corresponding accepted profile values. Overall mismatch if any mismatch, otherwise unknown if any unknown, otherwise match. Mark preferredResolution independently. Audio matches the first ranked profile choice present; `original` matches only actual language evidence equal to known movie originalLanguage. Missing or unrecognized original language cannot establish an original match or definite mismatch on that choice. Include audioPreferenceRank (one-based, nullable). Re-read source and settings after search; changed revisions return 409 rather than stale explanations. No profile mutation or selection/submission endpoint in this ticket. Durable snapshots, override confirmation and torrent identity are prerequisites of the later acquisition specification.
- REL-006: Library Search can register a TMDB result idempotently and open Releases. A Releases page lists/filter-pages registered movies without requiring TMDB; choose a movie, optionally a discovered category, then explicitly search and page candidates. Show source, known/unknown attributes, preferred resolution and each profile check in en-US/pt-BR. Display classified failures with Settings access, empty states, loading and pagination; preserve shared navigation/header/themes. Explain that source claims do not verify movie identity and this stage downloads nothing. Never offer a nonfunctional download button.

Additional errors: 404 catalog movie absent; 409 setup-required/source-capabilities-required/source-search-unsupported/source-test-in-progress/source-changed/preferences-changed; 422 validation-failed. Other source error statuses retain the ticket 01 contract. Search results are uncached observations; no schema migration or new dependency is needed.

## Slow-source reliability amendment

- REL-007: Release queries use a 65-second per-attempt deadline within a 70-second API budget and a route-specific 75-second write deadline. A timed-out release query is not automatically replayed; immediate transient network/5xx failures retain at most three retries and existing backoff/cooldown. Capability discovery retains SRC-003's short deadlines. Client cancellation aborts upstream work and releases source exclusion. The release UI offers Cancel and aborts on navigation. Explicit `cf-mitigated: challenge` or recognizable Cloudflare challenge HTML yields 502 `source-challenge-required`, distinct from authentication failure; generic 403 remains authentication failure. Never publish upstream HTML, cookies or credentials.

This supersedes REL-002's shared deadline policy. A longer deadline does not guarantee an upstream service will respond. Native direct adapters and managed browser handling are separate work.

## Direct source amendment

- NAT-001: Source GET/PUT gains `kind`, `torznab` (default for old/omitted input) or `1337x`. Additive migration 11 stores kind; old configurations, capabilities, credentials, catalog, jobs and acquisitions survive. No automatic conversion. Changing kind clears capabilities and requires explicit key clearing or replacement when an old credential exists; 1337x accepts no API key and requires an origin-only HTTP(S) URL. Older binaries reject schema 11; rollback restores a matching stopped-service backup.
- NAT-002: Direct 1337x testing loads `/cat/Movies/1/` and validates recognizable results or an explicit empty result. Advertise movie text search, Movies category 2000, maximum/default page size 20. Search original title with known year using `/category-search/<escaped query>/Movies/<page>/`; accept offsets in multiples of 20, clamp limit to 20 (smaller limits invalid for this fixed-page adapter). The site returns up to 40 raw rows; expose each half as a 20-row API page, preserving raw row positions for mixed-result pagination. Only known movie subcategories enter candidates; preserve provider ordering, nullable size/seeders and unknown audio. Use raw-page count/next-page evidence for pagination even when nonmovie rows are omitted. Mark malformed/changed HTML as invalid response, not an empty success.
- NAT-003: Browser runtime is an application-managed local child process, not an HTTP solver service. Pin InvisiblePlaywright and its dependencies; independently implement the adapter and challenge lifecycle rather than copying Byparr's GPL implementation. Browser context is ephemeral, with no persistent cookies or account profile. Limit each operation to 60 seconds inside the existing search/API budgets; one browser operation at a time, kill its process tree on cancellation. No automatic downloads/installations during ordinary requests. Runtime installation is explicit; missing runtime yields 503 `source-browser-unavailable`; unresolved challenges yield 502 `source-challenge-required`. Browser downloads/popups are disabled; Direct navigation outside the configured origin is blocked and the final page origin is checked before accepting results. A browser may contact an HTTP redirect destination before this check; these ephemeral sessions receive no saved source credentials. Challenge resources remain allowed for that page. Untrusted HTML is never rendered in the application.
- NAT-004: Persist details references privately as a typed `louro-1337x:` reference. Fetch a same-origin `/torrent/<numeric ID>/...` detail page only during explicit identity preparation; require a single unique magnet and apply existing v1 magnet validation before marking ready. Persist a verified resolved magnet in the existing private acquisition payload for restart/submission; never expose it publicly. Never follow advertised torrent mirrors or submit during search/preparation. Extend only source test and identity-preparation route budgets to 70 seconds/write deadline 75 seconds when needed. A failed browser/details lookup becomes a visible review code; retry remains explicit.
- NAT-005: Settings explains source kind, origin URL and local browser runtime requirements in en-US/pt-BR. Retain Torznab configuration and shared navigation/preferences. Direct source tests prove current page retrieval/parser compatibility, not future availability or correct movie identity.
- NAT-006: Validate through disposable SQLite/directories and fixture HTTP pages; cover migration failure/preservation/newer-schema refusal, malformed HTML, empty/paged/mixed results, redirects outside origin, duplicate magnets, timeouts/cancellation with no orphan processes, and selection-to-identity preparation. Verify Windows and non-root Linux browser runtime. Live challenge clearance is environment-dependent evidence, never a universal guarantee.

## Multiple saved sources amendment

- SRC-008: Additive migration 12 rebuilds `source_configuration` as a multi-row table with exactly zero or one active row. Preserve the existing row, credential, kind, capabilities, checked time and revision as the active source. Existing unconfigured installations remain empty. Older binaries reject schema 12; rollback restores a matching stopped-service backup.
- SRC-009: GET `/api/v1/sources` returns `activeSourceId` and every saved source in stable name/id order without credentials. POST `/api/v1/sources` creates an inactive source using the existing validation and write-only-key rules; duplicate normalized endpoints return 409 `source-exists`. A failed or repeated create cannot create duplicate endpoint rows.
- SRC-010: PUT `/api/v1/sources/{id}/active` requires that row's current revision and atomically activates it. Every create, edit or activation receives a database-wide monotonically increasing source revision, so switching between rows invalidates stale observations even when their original per-row revisions matched. Missing rows return 404; stale revisions return 409. Existing GET/PUT `/api/v1/source`, test and release routes continue to operate on the active row.
- SRC-011: Settings presents each saved indexer as its own tab, clearly identifies the active indexer, can add another Torznab or direct source, and requires explicit activation before editing/testing/searching it. The tab is the indexer; source type only selects its connection adapter. Typed keys remain write-only and are cleared after every attempt. Existing setup, localization, diagnostics and active-source controls remain available.
- SRC-012: Verify migration preservation/failure/newer-schema refusal, duplicate prevention, global revision monotonicity, stale activation, active-source compatibility, credential non-disclosure, restart persistence and localized browser flows using disposable databases and simulated providers.
