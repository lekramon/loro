# Domain documentation

This is a single-context repository. Read the root glossary before changing domain terminology and relevant architecture decisions before changing module boundaries, persistence, integrations, or file operations.

- Glossary: `GLOSSARY.md` at the repository root.
- Decisions: `docs/adr/`, numbered sequentially.
- Product behavior: `specs/000-product/spec.md`.
- Feature contracts: the relevant feature directory under `specs/`.

Use glossary terms consistently in code, specifications, tickets, and API descriptions. Record a new decision or explicitly supersede an existing ADR when changing architecture. Tests document observed behavior; specifications describe required behavior. Do not mark a criterion satisfied before its implementation has evidence.
